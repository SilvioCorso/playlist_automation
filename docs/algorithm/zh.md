# 匹配百分比如何计算

本文档**逐步**说明软件在将播放列表中的每首曲目与
您的音乐库对比时，如何为每首曲目分配百分比（**数值**列）。文末提供了多个**具体示例**及
详细计算过程。

> 简而言之：对于每个请求的曲目，软件使用**级联比较技术**在库中搜索最佳候选。
> 然后，如果**请求的标题完全包含**在找到的曲目中，则使用
> **会计模型**计算得分：从 **100%** 出发，减去精确的惩罚项。
> 如果标题仅部分匹配，则会启用**严格门槛**，大幅限制得分。

---

## 1. 绝对优先级：锁定（100% 保证）

在进行任何比较之前，软件会检查曲目是否**已锁定**。
如果是，得分为**固定 100%**，其余步骤全部跳过。

存在两种锁定类型：

1. **Composer lock** — `[lock]` 标签写入**音频文件的元数据**
   （composer 字段）。这是最稳健的方式：在文件移动和
   更换电脑后仍然有效。
2. **Title lock** — 您确认的*标题 → 文件*对应关系，
   保存在 `title_locks.json` 文件中。

两种情况下，只要请求的标题**包含**于
锁定曲目的标题中即可。要移除 100%，点击该行的锁图标
解锁：得分将按正常方式重新计算。

---

## 2. 搜索级联

如果曲目**未**锁定，软件按顺序尝试
以下技术来搜索最佳候选。**它在第一个产生有效结果的技术处停止。**

| # | 阶段 | 作用 |
|---|------|------|
| 1 | **Exact** | *规范化*后的艺人+标题完全相同 |
| 2 | **Word coverage** | 请求中的所有词都出现在曲目中 |
| 3 | **Composite** | 加权相似度：**艺人 30%** + **标题 70%** |
| 4 | **Fuzzy** | 对顺序和变体容错的「模糊」相似度 |
| 5 | **Title partial** | 仅对标题的部分相似度 |
| 6 | **Filename** | 与**文件名**比较（标签为空时很有用） |

### 「艺人 - 标题」结构

如果请求使用 **`艺人 - 标题`** 结构（带连字符，或
`:`、`|`、`/`），软件会将两个部分分开并分别使用：它知道
哪部分是艺人、哪部分是标题。这使计算更准确（参见
会计模型，§3）。

### 什么是「规范化」

比较前，文本会被清理，使无关差异
不计入结果：

- 全部转为**小写**；
- **编码修复（mojibake）**：以双重 UTF-8 编码保存的
  文本会被恢复，因此 `PreparÃ³` 会被读作 `Preparó`；
- **去除重音**（`Beyoncé` → `beyonce`，`Preparó` → `preparo`）；
- **下划线视为空格**（`Bellini_Music_Official` →
  `bellini music official`）；
- **标点**转为空格；
- **圆括号内的内容在比较时移除** — 例如
  `Titanium (Extended Mix)` → `titanium`（但括号内的词会
  单独评估，参见 §4）；
- 去除开头的冠词（`the`、`a`、`an`）和**四位数年份**。

得益于 mojibake 修复和去重音，`Preparó` 与
`PreparÃ³` 被视为**同一个词**。

### 对损坏文本（mojibake）的容错 + 文件名验证

有时标签以**无法自动重建**的方式损坏（例如
`PreparÃ3`，用数字代替重音）。此时软件**不会**立即将该词计为「不同」：如果 **Serato
标题**中出现可疑符号（`Ã`/`Â`），它会进行**文件名
比较**。如果正确且「干净」的词出现在 filename 中（例如 `preparo`），软件
会理解损坏的 token 实际上是同一个词，并**不
施加任何惩罚**。文件名因此充当「真相来源」。

## 3. 两种评分机制

选定候选后，软件检查**请求标题的所有词**是否**按相同顺序**
（作为子序列）出现在 **Serato 标题**或**文件名**中。

- **标题完全存在** → 使用**会计模型**（§4）：
  基础 **100%** 减去精确惩罚。
- **标题仅部分匹配** → 使用**严格门槛**（§5）：得分
  被限制在较低值（0%、44% 或 50%）。

---

## 4. 会计模型（标题完全找到）

从 **100%** 出发，减去以下惩罚。**所有惩罚
累加。**

| 情况 | 效果 |
|------|------|
| 请求中有**艺人**，但在找到曲目的任何列中**均未出现**（Artist、Song、Filename） | **上限 70%** |
| 找到曲目中有**多余的标题词**（真实词，非请求词，非低相关词） | **每个 −20%** |
| 找到曲目中有**多余的艺人词**（真实词，非请求词） | **总计 −5%** |
| 括号外的**低相关词**（remix、official、video、music…）未在请求中 | **总计 −5%** |
| **圆括号内**的任何词（描述词或未请求词） | **总计 −1%** |
| **请求标题**中的某个词**仅在文件名**中找到（不在 Song 或 Artist 中） | **−1%** |

重要说明：

- **多余的标题词**（例如请求为 *「Everything」*，但找到的曲目为
  *「Everything **she wants**」*）表明标题实际上不同：
  因此权重很大（**每个词 −20%**）。
- **多余的艺人词**权重较小（**总计 −5%**），因为通常只是
  上传者名称或变体（例如连写的 `ImagineDragons`，
  或像 `After Party82` 这样的频道）。
- **圆括号内**的词相关度更低：无论里面是什么，
  最多 **总计 −1%**。
- **艺人存在**检查是「宽松」的（`ImagineDragons`
  满足 `imagine`），而**多余词**计数是「精确」的
  （因此连写的 `ImagineDragons` 仍计为一个多余的艺人词）。

---

## 5. 严格门槛（标题仅部分匹配）

当请求的标题**未**按顺序完全存在时，匹配
不可靠，适用以下限制：

- **缺失词**：如果请求中的有意义的词未出现在
  曲目中 → **最高 50%**。
- **标题存在性**：如果标题词未出现在任何字段中 →
  **最高 45%**。
- **标题顺序**：标题词必须按相同顺序出现在
  文件名或 Serato 标题中：
  - 未找到任何词 → **0%**（行视为*缺失*）；
  - 找到但部分匹配 / 顺序错误 → **最高 44%**。
- **包含 bonus**：如果请求的标题仍包含在找到的标题中，
  得分至少升至 **62%**。
- **PSYTRANCE 调整**和**BPM 惩罚**（后者可选）可能
  作为微调介入。

---

## 6. 「低相关」词

这些是版本/格式/媒体描述词，**并不真正改变曲目本身**。
当它们出现在找到的曲目中但未出现在请求中时，不会使
得分崩溃：仅花费 **总计 −5%**（括号外）或 **总计 −1%**（若在
括号内）：

`remix`、`mashup`、`dub`、`vip`、`flip`、`bootleg`、`rework`、`discomix`、
`mashboot`、`remake`、`revibe`、`reloaded`、`original`、`extended`、`edit`、
`mix`、`version`、`radio`、`club`、`clean`、`dirty`、`official`、`oficial`、
`ufficiale`、`music`、`video`、`audio`、`mv`、`clip`、`lyric`、`lyrics`、
`visualizer`，以及比特率缩写如 `128kbit_AAC`、`320 kbps`。

## 8. 从得分到颜色与标签

最终得分决定行的**颜色**和置信度级别：

| 得分 | 置信度 | 行颜色（浅色主题） |
|------|--------|-------------------|
| 95–100% | 精确 | 纯绿色 |
| 75–94% | 高 | 绿色 |
| 55–74% | 中 | 橙/黄 |
| 1–54% | 低 | 浅红 |
| 0% | 缺失 | 粉/红（视为未找到） |

特殊颜色：

- **青色/浅蓝**：播放列表中两行或多行指向**同一文件**
  （请求中可能存在重复）。若从**已找到**列菜单
  更改版本且重复消失，颜色恢复正常。
- **▼ 加数字**在**已找到**列：有多个候选超过
  阈值 — 点击以选择正确版本。

## 9. 流程摘要

```
请求的曲目
   │
   ├─ 已锁定（composer/title lock）？ ── 是 ─▶ 100%
   │                                    否
   ▼
级联：Exact ▶ Word coverage ▶ Composite ▶ Fuzzy ▶ Title partial ▶ Filename
   │
   ▼
请求的标题是否完全（按顺序）存在于 Song 或 Filename 中？
   │
   ├─ 是 ─▶ 会计模型：100%
   │          − 艺人缺失时 30% 上限（基础降至 70%）
   │          − 每个多余标题词 −20%
   │          − 有多余艺人词 −5%
   │          − 括号外低相关词 −5%
   │          − 圆括号内有内容 −1%
   │          − 标题词仅在文件名中找到 −1%
   │
   └─ 否 ─▶ 严格门槛：
              缺失词 → 最高 50%
              标题存在性 → 最高 45%
              标题顺序 → 0% 或最高 44%
              （+ 包含 bonus、PSYTRANCE、BPM）
   ▼
最终得分（0–100%） ▶ 颜色 + 置信度标签
```
